# Implementation Plan

- [ ] 1. 個人マイページを `/dashboard` から `/dashboard/personal` へ移設する

- [x] 1.1 マイページ本体を新しいパスへ移設する
  - 既存のマイページ（プロフィール表示・サインアウト・所属組織一覧）のロジックを変更せず、`/dashboard/personal` で提供する。
  - 完了時、`/dashboard/personal` にアクセスすると既存と同じマイページ内容が表示され、旧パス `/dashboard` は存在しないページとして扱われることを確認する。
  - _Requirements: 1.1_

- [x] 1.2 ログイン後・招待受諾後の遷移先を新しいパスへ更新する
  - ログイン/サインアップ成功後のリダイレクト先、および招待受諾完了後の遷移先・リンクを `/dashboard/personal` に更新する。
  - 完了時、ログイン成功後と招待受諾完了後のいずれも `/dashboard/personal` へ遷移することを検証するテストが通過する。
  - _Requirements: 1.1_
  - _Depends: 1.1_

- [ ] 2. slug による組織コンテキスト解決基盤を実装する

- [ ] 2.1 slug から組織を解決する認可ロジックを実装する
  - 既存の組織アクセス認可（認証確認 → 組織存在確認 → メンバーシップ確認 → ロール確認）と同じ判定順序・失敗理由を、slug を入力とする経路でも提供する。slug は既存の組織作成時と同じ正規化規則（前後空白除去・小文字化）で解決する。
  - 保留中・拒否済み・期限切れ・無効な招待だけが存在する状態は、メンバーシップが作成されないため自然に「非所属」と判定されることを確認する。
  - 完了時、成功ケース、未認証、組織不存在、非所属、ロール不足、slug の大文字・前後空白ゆらぎの各ケースについて期待した判定結果を返すことを検証するテストが通過する。
  - _Requirements: 2.1, 3.1, 3.2, 3.3, 3.4_
  - _Boundary: OrganizationAuthz_

- [ ] 2.2 リクエスト単位で組織コンテキスト解決を再利用する仕組みを実装する
  - 同一リクエスト内で同じ slug に対する組織コンテキスト解決が複数回呼び出されても、実際の解決処理（DBアクセスを伴う判定）は1回に集約されるようにする。
  - 完了時、同一リクエスト内で同じ slug を複数回解決しても、下層の判定処理が1回しか実行されないことを検証するテストが通過する。
  - _Requirements: 2.2, 2.4_
  - _Depends: 2.1_

- [ ] 3. 所属組織の選択導線を実装する

- [ ] 3.1 (P) 組織一覧に組織を開く導線と未所属時の案内を追加する
  - 所属組織一覧の各組織に、その組織のコンテキスト画面へ遷移する導線を追加する。
  - 所属組織がない場合の案内文を、組織作成への導線に加えて招待を待つ旨も表示するよう更新する。
  - 完了時、所属組織がある場合は各組織から組織コンテキスト画面への遷移導線が表示され、所属組織がない場合は組織作成と招待待ちの両方を案内するメッセージが表示されることを検証するテストが通過する。
  - _Requirements: 1.1, 1.2, 1.3_
  - _Boundary: OrganizationList_
  - _Depends: 1.1_

- [ ] 3.2 (P) 所属組織専用の選択画面を新設する
  - `/dashboard/personal/organizations` で、未認証の場合はログイン画面へ移動させ、認証済みの場合は自分が所属する組織だけを一覧表示する（3.1 で更新した組織一覧表示・0件案内・組織を開く導線をそのまま利用する）。
  - 完了時、未認証でアクセスするとログイン画面へ移動すること、認証済みでアクセスすると所属組織のみが一覧表示され各組織から組織コンテキスト画面への遷移導線が表示されること、所属組織が0件の場合は3.1で定義した案内が表示されることを検証するテストが通過する。
  - _Requirements: 1.1, 1.2, 1.3_
  - _Boundary: PersonalOrganizationsPage_
  - _Depends: 1.1, 3.1_

- [ ] 4. `/dashboard/org/[orgSlug]` の組織コンテキストを実装する

- [ ] 4.1 組織コンテキストのアクセス制御と共通ヘッダーを実装する
  - `/dashboard/org/[orgSlug]` 配下を開いた際、未認証ならログイン画面へ移動させ、組織が存在しないか非所属なら404判定を発生させ、所属が確認できた場合のみ配下の画面共通で現在の組織名を表示するヘッダーを描画する。404判定発生時の画面内容自体は本タスクの範囲外とする（4.3が担当）。
  - 完了時、未認証時にログイン画面への移動が発生すること、組織不存在・非所属時に404判定が発生すること、所属確認済み時のみ組織名を含むヘッダーが描画されることを検証するテストが通過する。
  - _Requirements: 2.2, 2.3, 2.4, 3.1, 3.2, 3.3_
  - _Boundary: OrganizationLayout_
  - _Depends: 2.1, 2.2_

- [ ] 4.2 (P) 組織コンテキストの最小限のページを実装する
  - 所属が確認された組織について、組織名・slug・自分のロールを表示するコンテキスト画面を表示する。
  - 完了時、組織コンテキスト画面に組織名・slug・自分のロール（owner/member）が表示されることを検証するテストが通過する。
  - _Requirements: 2.2, 2.4_
  - _Boundary: OrganizationContextPage_
  - _Depends: 4.1_

- [ ] 4.3 (P) 不正slug・非所属時の404画面を実装する
  - 組織が存在しない場合と非所属の場合の両方で使われる、同一の404画面（組織情報を含まない案内とマイページへの導線）を単体で実装する。4.1 から発生する404判定によって表示されることを前提とするが、画面自体は4.1のロジックに依存せず単体で検証する。
  - 完了時、404画面に組織情報が一切含まれず、マイページへ戻る導線が表示されることを検証するテストが通過する。
  - _Requirements: 2.3, 3.3_
  - _Boundary: OrganizationNotFoundPage_

- [ ] 5. 組織選択から組織コンテキストまでの一連の流れを検証する
  - 所属組織の選択導線から組織コンテキスト画面への遷移、および非所属の組織 slug への直接アクセス時の404表示までを通しで確認する統合テストを作成する。
  - 完了時、組織選択から組織コンテキスト到達までの一連の流れと、非所属アクセス時の404表示を検証する統合テストが通過する。
  - _Requirements: 1.2, 2.2, 2.3, 2.4, 3.1, 3.3, 3.4_
  - _Depends: 3.1, 3.2, 4.2, 4.3_

- [ ] 6. 既存機能への回帰がないことを確認する
  - `/dashboard` の移設および新規ルート追加を反映した状態で、既存の全テスト・lint・ビルドを実行する。
  - 完了時、既存の全テスト・lint・ビルドがいずれも成功することを確認する。
  - _Requirements: 1.1_
  - _Depends: 5_
