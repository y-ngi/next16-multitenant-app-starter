# Implementation Plan

- [ ] 1. 組織・メンバーシップのスキーマ定義と開発環境適用を行なう

- [x] 1.1 組織スキーマの契約テストと実装を完了する
  - `src/db/schema.ts` に `organization` および `membership` を追加し、organization の識別子・名称・一意な slug、membership の user/organization 関係、`owner`/`member` の許可値、重複所属、参照整合性を検証する。
  - 開発およびテスト環境では `schema.ts` を正とし、`pnpm db:push` またはテスト DB 反映にてスキーマ更新を行い、契約テストを GREEN にする。
  - 完了時、組織スキーマ契約を含む全体テストが通過する。
  - _Requirements: 1.1, 2.1, 2.5, 6.1_

- [ ] 2. 認証オリジンと既存認証の継続性を確立する

- [x] 2.1 (P) canonical URL 設定の失敗テストを作成する
  - 認証サーバーとクライアントが同じ明示的 URL を使用し、Host または未信頼の転送ヘッダーで上書きされない期待を定義する。
  - 既存のメール/パスワード、メール検証、二段階認証、セッション設定を維持する期待を定義する。
  - 完了時、設定変更前には canonical URL と既存認証の継続性に関するテストが失敗する。
  - _Requirements: 4.1, 4.2, 5.1, 5.2_
  - _Boundary: Auth configuration_

- [x] 2.2 canonical URL 設定とプロキシ運用境界を実装する
  - 認証サーバー・クライアントを `BETTER_AUTH_URL` の canonical URL へ統一し、organization plugin を追加しない。
  - 環境変数例に必須 URL と、プロキシが信頼境界外の転送ヘッダーを制限する要件を追加する。
  - 完了時、2.1 のテストが通過し、必須 URL が欠ける構成は明示的に失敗する。
  - _Requirements: 4.1, 4.2, 5.1, 5.2, 5.3, 6.3_

- [ ] 3. サーバー側の組織認可契約を提供する

- [x] 3.1 組織認可の失敗・成功契約テストを作成する
  - 未認証、組織不存在、非所属、権限不足、組織ID改変を拒否し、owner/member の有効な所属だけを許可する期待を定義する。
  - 成功結果だけが organization ID、user ID、role を返すことを検証する。
  - 完了時、認可モジュール未実装状態で失敗するサーバー認可テストが存在する。
  - _Requirements: 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.2, 3.3, 3.4, 4.3_

- [x] 3.2 認証・所属・ロールを検証するサーバー認可を実装する
  - 組織操作ごとに既存セッション、organization、membership、必要 role を確認するサーバー専用の認可契約を実装する。
  - 未認証、組織不存在、非所属、権限不足を識別可能な失敗結果として返し、成功結果以外では保護情報を返さない。
  - 完了時、3.1 の成功・失敗シナリオが通過し、後続仕様が同じ契約を利用できる。
  - _Depends: 1.1_
  - _Requirements: 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.2, 3.3, 3.4, 4.3_

- [ ] 4. 一式開発完了後のマイグレーション生成と最終検証を行う

- [x] 4.1 本番用マイグレーション SQL の生成と整合性検証を行う
  - 開発およびテストが一通り完了した段階で、`drizzle-kit generate` 等を用いて `drizzle/` ディレクトリに本番用マイグレーション SQL ファイルを生成する。
  - 既存 DB（`push` 等で生成された既存の Better Auth 認証スキーマ等が存在する環境）に対してマイグレーションが破綻しないよう、baseline および加算マイグレーションの整合性を検証する。
  - _Depends: 1.1, 2.2, 3.2_
  - _Requirements: 4.1, 4.2, 6.1, 6.2, 6.3_

- [x] 4.2 DB再構築・マイグレーション適用と品質ゲートを実行する
  - ローカル DB をクリア/再構築し、生成されたマイグレーションを適用して全 unit/integration テスト、lint、型検査、プロダクションビルドを実行する。
  - 完了時、基盤の検証コマンドが全て成功し、失敗があれば組織機能を公開しない運用判断ができることを確認する。
  - _Depends: 4.1_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.2, 3.3, 3.4, 4.1, 4.2, 4.3, 5.1, 5.2, 5.3, 6.1, 6.2, 6.3_
