# Brief: organization-lifecycle

## Problem

ユーザは組織を作成できず、ほかのユーザを組織へ所属させる手段もない。そのためチームとしての利用を開始できない。

## Current State

認証済みユーザ向けのダッシュボードはあるが、組織、メンバーシップ、招待の永続化と画面/APIはいずれも存在しない。

## Desired Outcome

認証済みユーザが組織を作成でき、作成者は `owner` になる。`owner` はメールアドレスで招待でき、既存アカウントの招待先は本人の承認時に `member` として所属するか、拒否できる。承認による所属時には招待者へ通知する。未登録の招待先は、招待メールでメールアドレスを確認した後、確認済みのメールアドレスで登録を完了すると組織へ参加できる。招待先と異なるアカウントでリンクを開いたユーザには、招待先メールアドレスでの再ログインを促す。owner は招待履歴から招待先限定リンクを確認し、直接送付できる。組織メンバーは所属組織とメンバー一覧を確認できる。

## Approach

organization-foundation が導入する独自の組織・メンバーシップ・ロール基盤を利用する。組織のライフサイクルと招待状態はアプリケーションで管理し、既存のメール送信基盤を招待通知に利用する。未登録の招待先は、招待メールのリンクでメールアドレスを確認してから、確認済みのメールアドレスが固定された登録画面へ進む。招待作成、登録による参加、期限切れ、重複、無効な招待、および通知送信失敗の状態を画面へ明示する。

## Scope

- **In**: 組織作成、`owner` によるメール招待、既存アカウントの承認または拒否、未登録者の登録による参加、招待履歴と招待先限定リンクの確認、所属組織の一覧、メンバー一覧、招待ライフサイクルのエラー処理。
- **Out**: 組織検索による自己参加、実業務データ、詳細なメンバー権限変更、組織削除、`owner`/`member` 以外のロール。

## Boundary Candidates

- 組織作成と所属組織の取得
- 招待の送信、登録による参加、状態遷移

## Out of Boundary

- URL上の組織コンテキストと組織ページのガード
- 高権限のメンバー管理操作

## Upstream / Downstream

- **Upstream**: organization-foundation、既存のメール送信基盤、認証済みセッション
- **Downstream**: organization-context、organization-member-management

## Existing Spec Touchpoints

- **Extends**: organization-foundation
- **Adjacent**: `src/components/auth-form.tsx`、`src/app/dashboard/page.tsx`

## Constraints

招待はメールアドレスを宛先とする。既存アカウントは本人が招待を承認した時にのみ所属を作成し、拒否時には所属を作成しない。承認による所属時には招待者へ通知する。未登録の招待先は招待メールのリンクでメールアドレスを確認した後、その確認済みメールアドレスが固定された登録を完了した時にのみ所属を作成する。招待先と異なるアカウントで招待リンクを開いた場合は、そのアカウントでの招待利用を許可せず、招待先メールアドレスでの再ログインを促す。招待の有効期限は発行から14日間とし、同じ宛先への有効な未受諾招待がある場合は既存招待を無効化して新しい招待を発行する。通知送信に失敗しても招待は未受諾のまま維持し、owner は招待履歴から招待先限定リンクを直接送付できる。招待と認可に関わる状態検証はクライアントではなくサーバー側で行う。
