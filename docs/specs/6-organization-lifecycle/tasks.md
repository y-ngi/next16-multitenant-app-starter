# Implementation Plan

- [x] 1. invitation スキーマの契約テストと実装を完了する
  - `invitationStatusEnum`（`pending`/`accepted`/`rejected`/`expired`/`canceled`）と `invitation` テーブル（organizationId, email, role, 一意な token, status, inviterId, expiresAt, timestamps）を `src/db/schema.ts` に追加する。
  - 開発・テスト環境は `pnpm db:push` 等でスキーマを反映し、一意トークン制約・外部キー制約（cascade）・インデックスを検証する契約テストを先に作成してから GREEN にする。
  - 完了時、invitation スキーマ契約テストを含む全体テストが通過する。
  - _Requirements: 2.1, 2.5, 4.1, 4.2_

- [x] 2. 組織作成ロジックを実装する
  - 認証済みユーザーが name/slug を指定して組織を作成し、作成者を対象組織の `owner` としてメンバーシップへ登録する。
  - 未認証状態では組織を作成しないことをテストで検証する。
  - 完了時、組織作成に成功すると作成者がその組織を所属組織として取得できることを検証するテストが通過する。
  - _Requirements: 1.1, 1.2, 1.3_

- [ ] 3. 招待の発行を実装する

- [x] 3.1 (P) 招待メール送信基盤を実装する
  - Nodemailer を用いて招待メール（招待リンク付き）と、承諾時に招待者へ送る所属完了通知メールを送信する関数を実装する。
  - 送信失敗時は例外を捕捉し、呼び出し元へ送信可否を判定可能な結果で返す。
  - 完了時、送信成功時と送信失敗時それぞれの挙動を検証する単体テストが通過する。
  - _Requirements: 2.1, 2.3, 3.1_
  - _Boundary: InvitationMailer_

- [x] 3.2 招待作成ロジックを実装する
  - 対象組織の `owner` だけが招待を作成できることをサーバー側認可で検証し、owner 以外からの要求は招待を作成しない。
  - 招待先メールアドレスがすでに対象組織のメンバーである場合は重複した所属を作成せず、同一宛先への有効な未受諾招待が存在する場合は既存招待を `canceled` に更新してから新しい招待（発行から14日間有効、一意トークン）を発行する。
  - 招待作成後に招待メール送信を呼び出し、送信に失敗しても招待は `pending` のまま維持し、招待先限定リンクを結果に含めて返す。
  - 完了時、重複所属の拒否・再招待時の旧招待無効化・メール送信失敗時の招待維持と限定リンク返却をそれぞれ検証するテストが通過する。
  - _Requirements: 2.1, 2.2, 2.5, 4.1, 4.2, 5.3_
  - _Boundary: OrganizationLifecycle_
  - _Depends: 1, 3.1_

- [ ] 4. 招待への応答を実装する

- [ ] 4.1 招待トークンの検証ロジックを実装する
  - トークンから招待を照会し、存在しない・期限切れ（発行から14日経過）・使用済み（`accepted`/`rejected`）・`canceled` の各無効理由を区別した検証結果を返す。
  - 完了時、有効な招待および各無効理由のケースについて、それぞれ期待した検証結果が得られることを確認するテストが通過する。
  - _Requirements: 4.3_
  - _Depends: 1_

- [ ] 4.2 招待の承諾・拒否ロジックを実装する
  - ログイン中ユーザーのメールアドレスと招待先メールアドレスが一致する場合のみ承諾・拒否操作を受け付け、不一致の場合は識別可能な失敗理由を返す。
  - 承諾時は `member` としてメンバーシップを作成し招待を `accepted` に更新して招待者へ通知メールを送信し、拒否時は所属を作成せず招待を `rejected` に更新する。
  - 完了時、承諾成功・拒否・アカウント不一致のそれぞれについて期待した結果を返すことを検証するテストが通過する。
  - _Requirements: 2.3, 2.4, 4.4_
  - _Depends: 4.1, 3.1_

- [ ] 4.3 未登録招待先の登録による所属付与ロジックを実装する
  - 有効な招待に紐づくメールアドレスで新規ユーザー登録が完了した際に、当該ユーザーを対象組織へ `member` として自動的に所属させ、招待を `accepted` に更新する。
  - 完了時、未登録ユーザーが招待先メールアドレスで登録を完了すると、招待状態の更新と組織所属の作成が行われることを検証するテストが通過する。
  - _Requirements: 3.1, 3.2, 3.3_
  - _Depends: 4.1_

- [ ] 5. 所属組織・招待の一覧照会機能を実装する

- [ ] 5.1 招待履歴照会ロジックを実装する
  - 対象組織の `owner` が組織の招待一覧（宛先、実効ステータス、招待先限定リンクを含む）を取得できるようにし、`owner` 以外からの要求には招待履歴を返さない。
  - 実効ステータスは DB 上の `status` を書き換えず、`pending` かつ `expiresAt` が現在時刻を過ぎている場合に `expired` として算出して返す（4.1 の期限切れ判定ロジックを再利用する）。
  - 完了時、owner による招待一覧の取得、非 owner からの要求が拒否されること、期限切れ招待が一覧上で `expired` として表示されることをそれぞれ検証するテストが通過する。
  - _Requirements: 5.1, 5.2, 5.4_
  - _Depends: 3.2, 4.1_

- [ ] 5.2 所属組織一覧とメンバー一覧照会ロジックを実装する
  - 認証済みユーザーが自身の所属組織一覧を取得でき、所属する組織のメンバー一覧（表示名・メールアドレス・ロールを含む）を取得できるようにする。
  - 対象組織へ所属していないユーザーからの要求にはメンバー情報を返さない。
  - 完了時、所属組織一覧の取得、メンバー一覧の取得、非所属者への拒否をそれぞれ検証するテストが通過する。
  - _Requirements: 6.1, 6.2, 6.3_
  - _Depends: 2_

- [ ] 6. 画面を統合する

- [ ] 6.1 組織作成UIをダッシュボードへ統合する
  - 組織作成ダイアログを実装し、作成成功時に所属組織一覧を再取得してダッシュボードに反映する。
  - 完了時、ダッシュボードから組織を作成すると、作成した組織が所属組織一覧に表示される。
  - _Requirements: 1.1, 1.3, 6.1_
  - _Depends: 2, 5.2_

- [ ] 6.2 招待発行・履歴UIを実装する
  - 招待フォームと、招待履歴一覧（状態、招待先限定リンクのコピー操作、メール送信失敗時の警告表示）を実装する。
  - 完了時、招待作成後に履歴一覧へ新しい招待が反映され、メール送信失敗時には警告メッセージと招待先限定リンクが画面に表示される。
  - _Requirements: 2.1, 2.2, 5.1, 5.2, 5.3, 5.4_
  - _Depends: 3.2, 5.1_

- [ ] 6.3 招待承諾・拒否・無効表示画面を実装する
  - 招待受諾ページ（`/invitations/accept`）でトークンを検証し、無効・期限切れ（`expired`）・使用済み・キャンセル済みの各理由を区別して表示する。
  - ログイン中かつメールアドレスが一致する場合は承諾・拒否の操作を提示し、アカウント不一致の場合は「他のユーザへの招待ですので、招待されたメールアドレスで再ログインしてください。」と表示して再ログインへ誘導する。
  - ログインしていない場合は、後続タスク（6.4）で実装する固定メール登録導線へ遷移させる。
  - 完了時、承諾成功・拒否成功・アカウント不一致メッセージ・各無効理由（期限切れ/使用済み/キャンセル済み）の表示が画面上でそれぞれ確認できる。
  - _Requirements: 2.3, 2.4, 4.3, 4.4_
  - _Depends: 4.1, 4.2_

- [ ] 6.4 未登録招待先向けの登録導線をAuthFormへ統合する（AuthForm × InvitationAcceptPage 結合タスク）
  - `src/components/auth-form.tsx` に、招待トークンから渡された宛先メールアドレスを編集不可で固定表示する登録モードを追加する（現状は自由入力メール＋`/login` callback のみのため、招待経由の登録導線が存在しない）。
  - 招待受諾ページ（6.3）側で未登録ユーザーを検出した際にこの登録モードへ遷移させる呼び出し元コードを実装し、登録完了後は招待受諾ページへ戻して 4.3 の自動所属付与ロジックを呼び出すコールバック配線を行う。
  - 完了時、招待リンクから未登録メールアドレスで登録すると、メールアドレスが固定表示された登録フォームが表示され、登録完了後に対象組織への所属が付与されていることを画面操作で確認できる。
  - _Requirements: 3.1, 3.2, 3.3_
  - _Boundary: AuthForm, InvitationAcceptPage（両コンポーネントを接続する統合タスク）_
  - _Depends: 4.3, 6.3_

- [ ] 6.5 組織メンバー一覧UIを実装する
  - 所属組織のメンバー一覧（表示名、メールアドレス、ロール）を画面に表示する。
  - 完了時、組織メンバーがメンバー一覧画面で組織内の全メンバーを確認できる。
  - _Requirements: 6.2, 6.3_
  - _Depends: 5.2_

- [ ] 7. 組織ライフサイクル機能の品質ゲートを実行する
  - 対象の単体・統合テスト、lint、型検査、プロダクションビルドを実行する。
  - 完了時、基盤の検証コマンドがすべて成功し、失敗があれば組織ライフサイクル機能を公開しない運用判断ができる。
  - _Depends: 6.1, 6.2, 6.3, 6.4, 6.5_
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.2, 3.3, 4.1, 4.2, 4.3, 4.4, 5.1, 5.2, 5.3, 5.4, 6.1, 6.2, 6.3_
